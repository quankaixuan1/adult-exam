## 当前云开发版本

- 云环境：`cloud1-d2gcxozkl4c789619`。
- 小程序通过 `wx.cloud.callFunction` 调用 `student-api`，不再依赖 `BASE_URL`、局域网 IP 或本地 Express 才能运行。
- 学生身份由云函数上下文中的微信 `OPENID` 确定；前端传入的学生编号不作为账号归属依据。
- 云端使用 `students`、`registrations` 和 `audit_logs` 集合。`catalogs` 预留给后续后台维护学校专业，当前演示目录随云函数部署。

首次部署：在云开发控制台创建 `students`、`registrations`、`audit_logs`、`catalogs` 四个集合，四个集合均设为禁止小程序端直接读写。然后在微信开发者工具中右键 `cloudfunctions/student-api`，选择“上传并部署：云端安装依赖”。部署完成后重新编译小程序。

## 电脑管理后台

- `admin/`：Vue 3 + Vite 管理后台，连接当前 CloudBase 环境。
- `cloudfunctions/admin-api/`：管理员初始化、登录、统计、报名列表及审核接口。
- 需要额外创建 `admins`、`admin_sessions` 两个禁止客户端直接读写的集合，并为 Web SDK 开启匿名登录。
- 首次打开后台时，仅在 `admins` 为空的情况下显示主管理员初始化表单；密码通过 scrypt 加盐摘要保存，不写入前端源码。
- 管理会话有效期为 8 小时；审核操作写入 `audit_logs`。
- 本地预览可直接双击根目录 `start-admin.command`；重新构建可双击 `build-admin.command`。它们会在系统没有全局 `pnpm` 时使用当前 Mac 已有的 Codex Node 运行环境。构建产物位于 `admin/dist/`。

## 本次完成

- 每个微信在本小程序对应一个独立学生账号；再次登录返回同一账号，不用另设密码。
- 首页 →「微信登录 / 我的报名」→ 新考生填写报名 → 查看本人资料和进度。
- 一个账号保留一份当前报名资料；重复提交不会重复建档或覆盖已提交资料。
- 学生可修改联系电话、报考层次、意向专业；修改后重新进入待审核。姓名及账号归属不能自行修改。
- 退出当前登录后，该登录凭证立即失效；登录凭证有效期为 7 天。其他已登录设备的独立会话不会被当前设备退出操作清除。
- 打开账号页面时，已有登录状态会再次经微信确认当前身份，适应微信切换账号。
- 未配置微信密钥时拒绝登录，不提供模拟登录或通过客户端传入 OpenID 冒充账号的入口。

这建立的是微信关联的学生账号，不是考生实名核验。同一个人使用另一个微信仍可能建立新账号；真实考生去重、历史档案绑定需后续身份核验。

## 开通真实微信登录：还缺本机密钥配置

1. 使用小程序管理员账号进入微信公众平台，找到该小程序的 AppSecret。已有可用密钥就使用原密钥，不必重置。
2. 打开本项目 `.private/wechat.env`，在 `WECHAT_APP_SECRET=` 后填写密钥并保存。此文件只在本机，已被 Git 忽略；不要发到聊天、截图、前端源码或公开仓库。
3. AppID 默认读取 `project.config.json`，不需重复填写。若指定了环境变量 `WECHAT_APP_ID`，必须与项目一致。
4. 关闭旧的本地服务终端后，双击根目录 `start-local.command` 重启。看到“微信登录已配置”仅代表配置格式正确，仍需进行一次真实登录验证。
5. 微信开发者工具打开项目根目录，重新编译。首页 →「微信登录 / 我的报名」→「微信登录」，成功后显示学生账号编号。
6. 使用虚构报名信息进行提交测试；退出后再次微信登录，应看到同一账号与记录。

真正的微信 code 由 `wx.login` 取得，后端访问 `https://api.weixin.qq.com/sns/jscode2session` 完成兑换。服务端 AppSecret 与 session_key 不返回前端，不进入日志。当前未完成真实 AppSecret 联调，自动测试使用注入的模拟微信响应，不能等同于真实微信登录成功。

本地模拟器请求 `http://127.0.0.1:3000`。如开发者工具提示域名校验失败，本地调试需在「详情 → 本地设置」启用不校验合法域名的调试选项。服务只监听本机，手机预览不能通过 127.0.0.1 访问 Mac。不要直接发布这个本地版本。

## 权限与数据保护

- 所有本人资料接口都从服务端登录凭证确定学生 ID，忽略客户端指定的归属；没有公开名单和其他学生详情接口。
- SQLite 对微信身份映射和学生报名归属设置唯一约束，避免并发重复创建。
- 微信 OpenID 使用带密钥的摘要用于关联；会话凭证只保存 SHA-256 摘要。前端仅保存登录凭证、到期时间和内部学生 ID，不缓存姓名或手机号。
- 姓名、手机号、层次、专业采用 AES-256-GCM 加密；密钥和数据库放在仅当前用户可访问的 `.private/`。同机保存密钥不能抵御本机账户被控制。
- 修改采用版本检查，防止旧表单覆盖新数据；记入不含个人资料的事件日志。
- 本地限制请求体大小、接口频率并拒绝浏览器跨域请求；响应禁止缓存，异常不泄露服务端堆栈。
- `.private/`、数据库、Excel/CSV、环境配置与依赖不提交 Git。后端与密钥位于小程序打包目录之外。
- 正式使用前仍须补齐机构隐私说明、考生核验、管理员权限、生产 HTTPS、备份恢复和运维审计。

## 结构与运行

- `miniprogram/`：微信前端，`project.config.json` 指定为唯一打包根目录。
- `backend/core/`：账号与报名业务逻辑，不依赖 Express 或 SQLite。
- `backend/providers/wechat.js`：微信身份兑换；测试中可注入 provider，启动配置不提供 mock 模式。
- `backend/repositories/sqlite/`：账号、身份、会话、报名、事件日志与事务升级。
- `backend/local-server/`：本地配置与 HTTP 接口。
- `backend/tests/`：HTTP、账号权限、数据库迁移、微信适配和前端会话行为测试。
- `.private/`：数据库、密钥、微信本地配置及升级备份。不要删除或分享。

使用 Node.js 24。当前 Mac 的启动器兼容已安装的本地 Node 运行时；其他电脑安装 Node.js 24 后，执行 `pnpm install --frozen-lockfile` 和 `pnpm start`。测试：`pnpm test` 或 `node --test backend/tests/*.test.js`。

接口：

| 接口 | 用途 |
|---|---|
| GET /api/auth/config | 微信登录是否已配置，不返回密钥 |
| POST /api/auth/wechat | 提交临时 code，取得独立会话 |
| POST /api/auth/logout | 撤销当前会话 |
| GET /api/me | 当前学生账号 |
| GET /api/me/registration | 当前学生的报名资料 |
| POST /api/registrations | 当前学生报名，重复请求不重复建档 |
| PATCH /api/me/registration | 修改允许字段，并重新待审核 |
| GET /api/registrations/me/status | 仅兼容旧查询码的状态查询 |

账号接口使用 `Authorization: Bearer wxs_...`，旧查询码不能作为账号登录。账号和微信之间的关联由服务器兑换结果确定，没有可从前端自由修改绑定的 API。

迁移 CloudBase 时需实现同等的身份验证、会话有效期、唯一性和事务语义，不能仅替换数据库连接字符串。
